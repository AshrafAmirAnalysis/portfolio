Case Copilot

A browser assistant for CRM case handling
Chrome MV3 Dynamics 365 Client & Web API JavaScript jsdom test harness 350+ Tests

The Problem: Investigators on a trust & safety team handled each case through dozens of manual steps in a CRM: reading the case, writing an L1 summary, picking reply templates, composing customer emails, filling category fields, and walking the case through a multi-stage closing process. It was slow, repetitive, and prone to manual error.

My Role: Self-initiated and built solo while working as an investigator. Designed the product, authored specs, and shipped 40+ releases based on daily operational feedback with AI-assisted pair programming.

What it does

  • One-button quick actions: note with decision → reply → customer email → send → field macro → closure. Only decisions and confirmations require human input.
  • Multi-stage macro replay: Records and replays field updates cleanly across business process stages.
  • Structured hand-off: Builds an investigation package for downstream AI tools.
  • Flexible configuration: Team templates live in a shared spreadsheet so non-developers can adapt flows without code changes.

Engineering & Safety Highlights

  • DOM-Free Writes: Rebuilt from early fragile UI clicking onto Dynamics 365 client-side form APIs and REST Web APIs; DOM is used only for reading.
  • Pre-Write Identity Guards: Verifies open record ID matches target state before any write executes. SLA, timer, and datetime fields are permanently denylisted.
  • Root-causing flaky vendor scripts: Diagnosed a 90% failure rate in auto-composing emails down to timing, programmatic editor handling, and keyboard focus stalls.
  • Testing without a sandbox: Built a 350+ test jsdom mock suite covering pickers, flows, and end-to-end replay without needing a dedicated test environment.

Investigation Studio

A guarded web UI for an AI investigation agent
Node.js (Zero Deps) Claude Code Headless Model Context Protocol (MCP) SQL / Presto Streaming UI

The Problem: A CLI AI investigation agent querying data warehouses and searching internal knowledge worked well, but terminal workflows were unintuitive for operations teams, and an agent with database and document privileges required strict, verifiable guardrails.

My Role: Self-initiated and built solo. Designed the agent workflow, staged query playbooks, and the per-turn permission boundaries.

What it does

  • Light & Heavy Modes: Instant triage mode without database access, or full investigation mode with warehouse queries and memo drafting.
  • Live Streaming Activity: Every SQL query, result set, search, and file read is streamed live for continuous human auditability.
  • Human-in-the-Loop Sign-off: Document generation tools are unlocked only after human review and explicit approval.

Guardrail & Architecture Model

Turn Types & Permissions:

Turn Type Allowed Capabilities
Light Agent skill, file reads, knowledge base lookup. No database access.
Heavy Read-only data warehouse access + read-only document inspection.
Approve Document write/create unlocked strictly after human approval on qualifying findings.
